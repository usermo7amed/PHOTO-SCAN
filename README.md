# مُوحِّد الصور (Photo Unifier)

تطبيق Android لتحسين الصور على الجهاز، مع الحفاظ على الملفات الأصلية وحفظ الصور الناتجة في مجلد `Pictures/PhotoUnifier`.

## المزايا الحالية

- **اختيار ومعالجة مجموعة صور:** اختيار الصور من الجهاز ومعالجتها مع عرض تقدم العملية ومعاينات للأصل والنتيجة.
- **قياس ثم قرار:** قبل أي تعديل، يقيس التطبيق كل صورة (نسبة المناطق المحروقة والمظلمة، التباين، التشبع، ودرجة الصبغة اللونية للأسطح المحايدة) ولا يطبّق إلا التصحيحات التي تحتاجها الصورة فعلًا، وقوة كل تصحيح تتناسب مع حجم المشكلة وتتوقف عند سقف يناسب نوع الصورة. صورة سليمة لا تُمسّ. بعد المعالجة يعرض التطبيق لكل صورة سطرًا يوضح النوع الذي اختاره وما الذي تغيّر فيها.
- **تصنيف تلقائي:** يستخدم التطبيق نموذج ML Kit العام لاستخراج دلالات من الصورة، ثم يختار مسارًا للمستندات أو البوسترات أو الأماكن الداخلية أو الخارجية، مع الرجوع للمعالجة العامة عند ضعف الدلالات. يمكنك أيضًا اختيار النوع يدويًا من بطاقة **نوع المعالجة**.
- **اكتشاف الورقة تلقائيًا حتى بدون تسمية:** إذا ظهرت في الصورة ورقة أو بوستر واضح (كبير، مستطيل الشكل، وحوافه حقيقية، ويختلف عن خلفيته)، يقصّه التطبيق ويعدّل المنظور ويعالجه كمستند أو بوستر حسب ألوانه، حتى لو لم يتعرف عليه ML Kit. الصور العادية لا تُقص.
- **معالجة حسب نوع الصورة:**
  - **الصور الداخلية:** ضبط توازن الأبيض (عند وجود صبغة لونية فعلية)، ورفع الظلال وخفض السطوع العالي محليًا، وتباين محلي.
  - **الصور الخارجية:** استعادة تفاصيل السماء والجدران المحروقة دون تحويل الأسطح البيضاء الحقيقية إلى رمادي، وبدون تغيير ألوان المشهد.
  - **البوسترات:** معالجة أكثر هدوءًا للحفاظ على الألوان.
  - **المستندات:** توحيد بياض الورقة وإزالة الظلال عنها (الحبر والكتابة لا يدخلان في تقدير مستوى الورق)، مع الإبقاء على لون الحبر والأختام.
- **توحيد الشكل بين الصور:** مؤشر **توحيد الشكل بين الصور** يقرّب سطوع الصور وتباينها وصبغتها اللونية من الشكل المتوسط للمجموعة، أو من **صورة مرجعية** تختارها. القيمة 0 تعني ترك كل صورة كما هي. المستندات والبوسترات لا تدخل في التوحيد.
- **قص المستندات وتصحيح المنظور يدويًا:** من قسم معاينة الصورة، افتح «تحديد زوايا الورقة». يحاول التطبيق اكتشاف حدود الورقة تلقائيًا، ثم يعرض أربع نقاط قابلة للسحب ومعاينة حية للقص وتصحيح المنظور.
- **أدوات تعديل القص:** تقدر تسحب الزوايا، وتتراجع عن التعديلات، أو تعيد ضبط الحدود، أو تلغي العملية، أو تطبق القص. لو اكتشاف الورقة فشل، يبدأ المحرر بإطار الصورة كاملًا لتعديل الزوايا يدويًا.
- **ضبط السطوع والتباين:** قبل حفظ النتيجة.
- **التعامل مع الصور الكبيرة:** الصور التي يزيد طول ضلعها عن 4096 بكسل تُصغّر مؤقتًا لتقليل استهلاك الذاكرة أثناء المعالجة.

## طريقة استخدام قص المستند

1. اختَر صورة واحدة أو أكثر.
2. افتح قسم **معاينة الصورة** واضغط **تحديد زوايا الورقة**.
3. راجع الزوايا الأربع الظاهرة فوق الصورة، واسحب أي نقطة لتطابق حدود الورقة.
4. راجع **معاينة القص**. استخدم **تراجع** لاسترجاع آخر موضع، أو **إعادة ضبط** للرجوع إلى إطار الصورة الكامل.
5. اضغط **تطبيق القص**، ثم ابدأ التحسين. القص اليدوي يُطبّق على **الصورة الأولى المختارة فقط**؛ باقي الصور تتابع المعالجة المعتادة، ولا يبحث التطبيق عن ورقة ثانية داخل صورة قصصتها بيدك.

## حدود معروفة

- نموذج ML Kit المستخدم نموذج تصنيف عام جاهز (حوالي 450 تسمية)، وليس نموذجًا مخصصًا ومدرّبًا على فئات التطبيق الأربع، وكثير من الكلمات الشائعة مثل document وtext وindoor وoutdoor ليست ضمن تسمياته. لذلك قد يختار مسارًا غير مناسب لبعض الصور، وعندها استخدم **نوع المعالجة** لاختيار النوع بنفسك.
- المعالجة الحالية جُرّبت على صور تركيبية وصورة واحدة حقيقية فقط (جدار ومبنى خارجي شديد الإضاءة)، ولم تُجرَّب على جهاز Android حقيقي بعد. جودة النتائج على صورك هي الاختبار الحقيقي؛ أرسل الحالات التي لا تعجبك لضبط الأرقام.
- أسطح المبنى البيضاء الحقيقية تبقى فاتحة بعد المعالجة؛ التطبيق يستعيد التفاصيل الموجودة ولا يحوّل الأبيض إلى رمادي. وما سُجّل أسود تمامًا يُرفع قليلًا فقط، لأن رفعه أكثر يضخّم الضوضاء.
- اكتشاف حدود الورقة يعتمد على تقنيات OpenCV التقليدية، وقد يفشل مع الخلفيات المتشابهة أو الإضاءة الضعيفة أو الأوراق المثنية. عندها يمكن ضبط الزوايا يدويًا.
- القص اليدوي يتطلب أن تكون مكتبة OpenCV جاهزة. كما أن صلاحية الشكل الرباعي تُراجع قبل تطبيق التحويل، لكن ذلك لا يضمن أن الزوايا تطابق حدود الورقة بصريًا.
- إزالة الظلال لا تستعيد تفاصيل فُقدت بالفعل بسبب الاحتراق الضوئي أو التصوير بالأبيض والأسود.
- الصور الأصلية لا يتم تعديلها؛ تُحفظ النتائج في مجلد منفصل.

## البناء والاختبارات

المشروع يستخدم Java 17 وGradle 8.7 وAndroid Gradle Plugin 8.5.2. من جذر المشروع شغّل:

```bash
gradle testDebugUnitTest assembleDebug --no-daemon --stacktrace
```

أو ادفع التغييرات إلى فرع `main`؛ GitHub Actions يشغّل الاختبارات والبناء ويرفع ملف APK كـ Artifact باسم `photo-unifier-debug`.

تشمل اختبارات الوحدة التحقق من صلاحية زوايا القص، وقياس الصورة وقرارات المعالجة (`ImageMetrics` و`TonePlanner`)، وحسابات توحيد الشكل (`LookMatcher`)، وحسابات اكتشاف الورقة (`PageMath`)، وتصنيف ML Kit. وهذه كلها منطق Kotlin بحت لا يحتاج جهازًا. وتوجد اختبارات Python تركيبية لخوارزميات OpenCV:

```bash
pip install opencv-python-headless numpy
python -m unittest discover -s tools/prototype/tests -v
python tools/prototype/enhance.py input.jpg before_after.jpg --mode document
python tools/prototype/enhance.py input.jpg before_after.jpg --mode detect   # يختار مستند/بوستر لو في ورقة واضحة
```

الأنماط المتاحة في النموذج التجريبي: `auto` و`interior` و`exterior` و`document` و`poster` و`detect`. الأرقام (الحدود والسقوف) واحدة في النموذج وفي كود Kotlin، فاضبطها في النموذج على صورك أولًا ثم انسخها. النموذج التجريبي لا يشغّل ML Kit؛ التصنيف التلقائي موجود في تطبيق Android.
